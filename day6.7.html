Cloud Services & Deployment

1. Firebase: Backend-as-a-Service (BaaS)

Firebase is a platform by Google that provides backend services like Database, Authentication, and Hosting without you needing to manage a server.

Real-World Analogy: The Vending Machine
Building your own backend is like opening a restaurant. You need to hire chefs (coders), rent a kitchen (server), and buy ingredients (database).

Using Firebase is like using a Vending Machine. You don't worry about how the machine works or who stocked it. You just press a button (API Call) and get your item (Data). It's instant and requires zero maintenance.
Step 1: Setup
  1. Go to Firebase Console and create a project.
  2. Register your app (Web) and copy the firebaseConfig object.
  3. Install the SDK: npm install firebase
Step 2: Initialize (`src/firebase.js`)
import { initializeApp } from "firebase/app";
import { getAuth } from "firebase/auth";

const firebaseConfig = {
  apiKey: "AIzaSyD...",
  authDomain: "myapp.firebaseapp.com",
  projectId: "myapp",
  storageBucket: "myapp.appspot.com",
  messagingSenderId: "123456",
  appId: "1:123456:web:abc"
};

// Initialize Firebase
const app = initializeApp(firebaseConfig);

// Export services you need (e.g., Auth)
export const auth = getAuth(app);

2. Testing React Components

Testing ensures your code works as expected before users see it. We use Vitest (a fast test runner) and React Testing Library.

Real-World Analogy: The Car Crash Test
Before a car company sells a new model, they perform crash tests with dummies. They don't wait for a real customer to crash to see if the airbags work.

Similarly, we write Unit Tests to "crash" our components in a safe environment to ensure they behave correctly before deploying.
Step 1: Install Tools
npm install -D vitest jsdom @testing-library/react
Step 2: Write a Test (`src/Header.test.jsx`)
import { render, screen } from '@testing-library/react';
import { describe, it, expect } from 'vitest';
import Header from './Header';

describe('Header Component', () => {
  it('renders the correct title', () => {
    const testTitle = "My Test Title";
    
    // 1. Render the component in a virtual DOM
    render(<Header title={testTitle} />);

    // 2. Check if the text exists
    const headingElement = screen.getByText(testTitle);
    
    // 3. Assert that it is in the document
    expect(headingElement).toBeInTheDocument();
  });
});

Run tests using: npm test

3. Deployment to AWS S3

AWS S3 (Simple Storage Service) is a storage service, but it can also host static websites (like React apps) very cheaply.

Real-World Analogy: The Digital Billboard
Running a server (like Node.js) is like hiring a person to stand on the street and hand out flyers. You have to pay them hourly, even if no one walks by.

AWS S3 is like renting a Billboard. You paste your poster (your built React files) on it once. It stays there 24/7, requires no staff, and costs pennies.
Step 1: Build for Production

This converts your code into optimized HTML, CSS, and JS files in a dist folder. 

npm run build
Step 2: Configure S3 Bucket
  1. Create Bucket: Go to AWS Console → S3 → Create Bucket. Name it (e.g., my-fintech-app-2026).
  2. Enable Hosting: Go to Properties → Static website hosting → Enable. Set Index document to index.html.
  3. Public Access: Go to Permissions → Uncheck "Block all public access".
  4. Bucket Policy: Add a policy to allow anyone to read the files:
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
        }
    ]
}
Step 3: Upload

Upload the contents of your dist folder (not the folder itself) to the bucket.
