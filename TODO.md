## 🔹 Query Params

* Data sent in the **URL after a question mark**
* Used for **filtering, searching, sorting**
* Optional parameters (not required)

👉 Example idea:
`?name=rahul&age=25`

✔ Used when:

* Searching users
* Filtering data
* Pagination

---

## 🔹 Path Params (Params)

* Data sent as part of the **URL path**
* Used to identify a **specific resource**
* Usually required

👉 Example idea:
`/users/123`

✔ Used when:

* Get user by ID
* Update specific record
* Delete specific item

---

## 🧠 Key Difference

* Query Params → extra info (optional, flexible)
* Path Params → main identifier (required, fixed)

## 🔹 Try Catch (Simple Explanation)

**Try Catch** is used to handle errors safely.

* **try** → write the code you want to run
* **catch** → runs if an error happens

---

## 🧠 Simple Idea

* Try = “I will try this code”
* Catch = “If something goes wrong, handle it here”

---

## 🎯 Why we use it

* Prevent app crash
* Handle errors smoothly
* Show proper messages instead of breaking

---

## 📌 Example in real life

* Try → You try to open a file
* Catch → If file not found, show error message instead of crashing

---

## ✅ One-line interview answer

Try Catch is used to handle runtime errors so the program does not crash.
## 🔹 Async / Await (Simple Explanation)

**Async / Await** is a way to handle asynchronous operations (like API calls) in a **clean, readable way**.

* **async** → marks a function as asynchronous (it returns a Promise)
* **await** → waits for the Promise to resolve before moving to the next line

---

## 🧠 Simple Idea

* Async = “this function works asynchronously”
* Await = “pause here until the result comes”

---

## 🎯 Why we use it

* Makes async code look **like normal synchronous code**
* Easier to **read and debug**
* Works well with **try / catch** for error handling

---

## 📌 Real-life analogy

* Async = You order food online
* Await = Wait until delivery arrives before eating

---

## ✅ One-line interview answer

Async / Await is used to write asynchronous code in a readable way, waiting for results without blocking the program.
