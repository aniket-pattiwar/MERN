Why is it required?

React builds Single Page Applications (SPAs). Without a router, you can't have different URLs (like /about, /contact) or browser history (back button support) without reloading the page.

Alternatives?
  • Conditional Rendering: { page === 'home' && <Home /> } (Messy for big apps).
  • Other Libraries: TanStack Router, Wouter.

2. Implement Routing in `App.jsx`
import { BrowserRouter, Routes, Route, Link } from 'react-router-dom';
import Home from './Home';
import About from './About';

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link> | <Link to="/about">About</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}

⭐ Conditional Rendering in React

Conditional Rendering in React works the same way conditions work in JavaScript. It allows your UI to render different elements or components based on certain state or prop conditions.

1. Ternary Operator (condition ? A : B)

Ideal for binary (either/or) conditions:

function UserGreeting({ isLoggedIn }) {
  return (
    <div>
      {isLoggedIn ? (
        <h5 class="text-success">Welcome back, Member!</h5>
      ) : (
        <button class="btn btn-primary">Please Sign In</button>
      )}
    </div>
  );
}

2. Logical AND Operator (condition && A)

Ideal when you only want to render something when condition is true:

function NotificationBell({ unreadCount }) {
  return (
    <div>
      <span>Inbox</span>
      {unreadCount > 0 && (
        <span class="badge bg-danger ms-2">
          {unreadCount} New
        </span>
      )}
    </div>
  );
}
3. Early Return Pattern (if / else)

Ideal for loading spinners or error screens:

function BookDetails({ book, isLoading, error }) {
  if (isLoading) return <div class="spinner-border text-primary" role="status" />;
  if (error) return <div class="alert alert-danger">{error}</div>;
  if (!book) return <p>No book found.</p>;

  return <h4>{book.title} by {book.author}</h4>;
}
4. Switch / Object Lookup Pattern

Ideal for multi-state conditions (e.g. Order Status):

function OrderBadge({ status }) {
  const badgeStyles = {
    pending: 'badge bg-warning text-dark',
    completed: 'badge bg-success',
    cancelled: 'badge bg-danger'
  };

  return (
    <span className={badgeStyles[status] || 'badge bg-secondary'}>
      {status.toUpperCase()}
    </span>
  );
}
💡 Simple Analogy A Room Light Switch or Weather App

If it's sunny outside, you don't need an umbrella; if it's raining, you open it. In React, if a user is logged in, you show a 'Logout' button; if they are logged out, you show a 'Login' button. That is Conditional Rendering: showing different UI based on state.

2. Classes vs. Hooks: The Evolution

What was the primary reason the React team introduced Hooks (such as useState and useEffect) in React 16.8?

React originally used Class Components. In 2018, Hooks were introduced to make Functional Components powerful. Hooks are now the industry standard.

Feature Class Components (Old) Functional Components + Hooks (New)
Syntax class App extends React.Component function App()

Lifecycle componentDidMount() useEffect()
Complexity High (requires this binding) Low (Standard JavaScript functions)
Class Structure
class Counter extends Component {
  constructor() {
    this.state = { count: 0 };
  }
  render() {
    return <div>{this.state.count}</div>
  }
}
Hook Structure
function Counter() {
  const [count, setCount] = useState(0);
  
  return <div>{count}</div>
}

3. Essential Hooks Toolkit

Hooks are like tools in a toolbelt. You grab only what you need.

Hook Name Role / Purpose Example
useState Memory. Stores data that changes. Input form text, Counter value, Toggle switch.
useEffect Side Effects. Runs code after render. Fetching API data, Setting a timer, Updating document title.
useContext Global Data. Avoids prop drilling. User login status, Dark/Light theme preference.
useRef DOM Access. Reference elements directly. Focusing an input field automatically.
useParams URL Data. Reads dynamic URL parts. Getting 123 from /product/123.

3.5. Examples

1. The Digital Clock

Goal: Display a clock that updates every second.

  • useState: Stores the current time string (e.g., "10:45:01 AM").
  • useEffect: Sets up a timer that updates the state every 1000ms. It also cleans up the timer when the component is removed to stop it from running in the background.
2. Window Size Tracker

Goal: Detect if the user is on Mobile or Desktop by tracking window width.

  • useState: Stores the current width number (e.g., 1024).
  • useEffect: Attaches a "resize" event listener to the browser window. When the user resizes, it updates the state. It removes the listener when done to avoid memory leaks.

5. Why does it reset on refresh?

Problem: When the page is refreshed, the like count resets to its initial value. This happens because useState stores data in memory (RAM), which gets cleared whenever the page reloads.

Example:
  • React State (RAM): Like writing on a whiteboard. If you wipe it (refresh), it's gone.
  • Database/Storage: Like carving into stone or writing in a diary. It stays even if you leave the room.
Solution: Local Storage + useEffect

To keep the value persistent like on YouTube, it can be stored whenever it updates. This can be done using the browser's Local Storage.

import React, { useState, useEffect } from 'react';

function PersistentLikeCounter() {
  const [likes, setLikes] = useState(
    () => {
    const savedValue = localStorage.getItem('my_likes');
    return savedValue ? parseInt(savedValue) : 0;
  }
  );

  useEffect(() => {
    localStorage.setItem('my_likes', likes);
  }, [likes]);

  return (
    <div>
      <h3>Persistent Counter</h3>
      <button onClick={() => setLikes(likes + 1)}>
        Likes: {likes}
      </button>
      <p><small>(Try refreshing the page!)</small></p>
    </div>
  );
}

// CounterApp.jsx - Complete runnable useState and useEffect Demo
import React, { useState, useEffect } from 'react';

export default function CounterApp() {
  // 1. useState: Initialize count from localStorage or default to 0
  const [count, setCount] = useState(() => {
    const saved = localStorage.getItem('mern_counter');
    return saved !== null ? parseInt(saved, 10) : 0;
  });

  const [themeDark, setThemeDark] = useState(false);

  // 2. useEffect: Sync count changes to browser localStorage
  useEffect(() => {
    localStorage.setItem('mern_counter', count.toString());
    console.log(`[useEffect] Persisted counter to localStorage: ${count}`);
  }, [count]); // Runs whenever 'count' changes

  return (
    <div style={{
      fontFamily: 'sans-serif',
      padding: '24px',
      maxWidth: '450px',
      margin: '40px auto',
      borderRadius: '12px',
      textAlign: 'center',
      backgroundColor: themeDark ? '#1e293b' : '#f8fafc',
      color: themeDark ? '#f8fafc' : '#0f172a',
      boxShadow: '0 4px 12px rgba(0,0,0,0.1)'
    }}>
      <h2>⚡ React Hooks Interactive Lab</h2>
      <p>State persists even when you refresh the browser!</p>
      
      <div style={{ fontSize: '48px', fontWeight: 'bold', margin: '16px 0' }}>
        {count}
      </div>

      <div style={{ display: 'flex', gap: '8px', justifyContent: 'center' }}>
        <button onClick={() => setCount(c => c - 1)} style={{ padding: '8px 16px', fontSize: '18px' }}>-</button>
        <button onClick={() => setCount(0)} style={{ padding: '8px 16px', fontSize: '18px' }}>Reset</button>
        <button onClick={() => setCount(c => c + 1)} style={{ padding: '8px 16px', fontSize: '18px' }}>+</button>
      </div>

      <hr style={{ margin: '20px 0', borderColor: '#ccc' }} />

      {/* Conditional Rendering */}
      <button 
        onClick={() => setThemeDark(prev => !prev)}
        style={{ padding: '8px 16px', cursor: 'pointer', borderRadius: '6px' }}
      >
        {themeDark ? '☀️ Switch to Light Mode' : '🌙 Switch to Dark Mode'}
      </button>

      {count >= 10 && (
        <div style={{ marginTop: '16px', color: '#16a34a', fontWeight: 'bold' }}>
          🎉 Milestone reached: Double digits!
        </div>
      )}
    </div>
  );
}
How it works: Combines useState for responsive state updates, useEffect with a dependency array [count] to synchronize with browser localStorage, and conditional rendering using logical && and ternary operators.

6. Why did we need these Hooks?

Goal Without Hook / Old Class Way With Hook (Functional Component)
Remembering "Likes"
(State Management) 		Variable: let likes = 0;
Problem: React doesn't know it changed, so the UI never updates. When the component re-renders, the variable resets to 0.

Old Class: this.state = { likes: 0 } 		Hook: useState(0)
Solution: React "hooks" into this variable, remembers it between renders, and updates the UI automatically when it changes.
Saving to Storage
(Side Effects)		 Manual: Writing localStorage.setItem directly in the function body.
Problem: It runs on every single render, slowing down the app.

Old Class: componentDidUpdate() 		Hook: useEffect(..., [likes])
Solution: It runs only when likes changes. It's precise and efficient automation.
