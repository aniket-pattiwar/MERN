Why is it required?

React builds Single Page Applications (SPAs). Without a router, you can't have different URLs (like /about, /contact) or browser history (back button support) without reloading the page.

Alternatives?
  • Conditional Rendering: { page === 'home' && <Home /> } (Messy for big apps).
  • Other Libraries: TanStack Router, Wouter.
1. Page Components

Create two files in src folder:


export default function Home() {
  return <h2>Home Page</h2>;
}


export default function About() {
  return <h2>About Us</h2>;
}
2. Implement Routing in `App.jsx`
import { BrowserRouter, Routes, Route, Link } from 'react-router-dom';
import Home from './Home';
import About from './About';

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link> | <Link to="/about">About</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}
3. Entry Point (`main.jsx`)

Do not need to remove <React.StrictMode>. It works perfectly with React Router. Keep it to catch potential problems.

import React from 'react'

2. Classes vs. Hooks: The Evolution

React originally used Class Components. In 2018, Hooks were introduced to make Functional Components powerful. Hooks are now the industry standard.

Feature Class Components (Old) Functional Components + Hooks (New)
Syntax class App extends React.Component function App()
State this.state = { count: 0 } const [count, setCount] = useState(0)
Lifecycle componentDidMount() useEffect()
Complexity High (requires this binding) Low (Standard JavaScript functions)
Class Structure
class Counter extends Component {
  constructor() {
    this.state = { count: 0 };
  }
  render() {
    return <div>{this.state.count}</div>
  }
}
Hook Structure
function Counter() {
  const [count, setCount] = useState(0);
  
  return <div>{count}</div>
}

3. Essential Hooks Toolkit

Hooks are like tools in a toolbelt. You grab only what you need.

Hook Name Role / Purpose Example
useState Memory. Stores data that changes. Input form text, Counter value, Toggle switch.
useEffect Side Effects. Runs code after render. Fetching API data, Setting a timer, Updating document title.
useContext Global Data. Avoids prop drilling. User login status, Dark/Light theme preference.
useRef DOM Access. Reference elements directly. Focusing an input field automatically.
useParams URL Data. Reads dynamic URL parts. Getting 123 from /product/123.

3.5. Examples

1. The Digital Clock

Goal: Display a clock that updates every second.

  • useState: Stores the current time string (e.g., "10:45:01 AM").
  • useEffect: Sets up a timer that updates the state every 1000ms. It also cleans up the timer when the component is removed to stop it from running in the background.
2. Window Size Tracker

Goal: Detect if the user is on Mobile or Desktop by tracking window width.

  • useState: Stores the current width number (e.g., 1024).
  • useEffect: Attaches a "resize" event listener to the browser window. When the user resizes, it updates the state. It removes the listener when done to avoid memory leaks.

4. The "Like" Counter (useState)

Build a "Like" button feature found in social media apps.

React Hooks

This is a great post about React!

Clicking updates the number instantly
import React, { useState } from 'react';

function LikeCounter() {
  const [likes, setLikes] = useState(42);

  return (
    <div className="card">
      <h5>Post Title</h5>
      <p>This is a great post about React!</p>
      
      <button onClick={() => setLikes(likes + 1)}>
        Likes: {likes}
      </button>
    </div>
  );
}

5. Why does it reset on refresh?

Problem: When the page is refreshed, the like count resets to its initial value. This happens because useState stores data in memory (RAM), which gets cleared whenever the page reloads.

Example:
  • React State (RAM): Like writing on a whiteboard. If you wipe it (refresh), it's gone.
  • Database/Storage: Like carving into stone or writing in a diary. It stays even if you leave the room.
Solution: Local Storage + useEffect

To keep the value persistent like on YouTube, it can be stored whenever it updates. This can be done using the browser's Local Storage.

import React, { useState, useEffect } from 'react';

function PersistentLikeCounter() {
  const [likes, setLikes] = useState(
    () => {
    const savedValue = localStorage.getItem('my_likes');
    return savedValue ? parseInt(savedValue) : 0;
  }
  );

  useEffect(() => {
    localStorage.setItem('my_likes', likes);
  }, [likes]);

  return (
    <div>
      <h3>Persistent Counter</h3>
      <button onClick={() => setLikes(likes + 1)}>
        Likes: {likes}
      </button>
      <p><small>(Try refreshing the page!)</small></p>
    </div>
  );
}

6. Why did we need these Hooks?

Goal Without Hook / Old Class Way With Hook (Functional Component)
Remembering "Likes"
(State Management) 		Variable: let likes = 0;
Problem: React doesn't know it changed, so the UI never updates. When the component re-renders, the variable resets to 0.

Old Class: this.state = { likes: 0 } 		Hook: useState(0)
Solution: React "hooks" into this variable, remembers it between renders, and updates the UI automatically when it changes.
Saving to Storage
(Side Effects)		 Manual: Writing localStorage.setItem directly in the function body.
Problem: It runs on every single render, slowing down the app.

Old Class: componentDidUpdate() 		Hook: useEffect(..., [likes])
Solution: It runs only when likes changes. It's precise and efficient automation.
