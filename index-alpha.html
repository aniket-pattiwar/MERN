What is the MERN Stack?

The MERN stack is a popular and powerful collection of technologies used to build full-stack web applications.

  • MongoDB: A NoSQL, document-based database.
  • Express.js: A back-end web application framework for Node.js.
  • React: A front-end JavaScript library for building user interfaces.
  • Node.js: A back-end JavaScript runtime environment that runs code on the server.

Together, these components allow you to build a three-tier architecture (frontend, backend, database) entirely with JavaScript and JSON.

MongoDB Fundamentals & Lab

Relational (SQL) vs. NoSQL Databases

Relational Databases (e.g., MySQL, PostgreSQL)

  • Data is stored in tables with rows and columns.
  • A strict schema defines the table structure, data types, and relationships.
  • Uses SQL (Structured Query Language).

NoSQL Databases (e.g., MongoDB, Cassandra, Neo4j)

  • Data can be stored in various formats like document (JSON-like), key-value, graph.
  • Flexible or dynamic schema allows for storing varied data structures.
  • Built for scalability and high performance.

MySQL databases → use SQL
SELECT * FROM users WHERE age > 25;

MongoDB → uses MQL (JSON-style queries)
db.users.find({ age: { $gt: 25 } })

Lab: Aggregation Pipeline

The aggregation pipeline is a powerful framework for data analysis. It processes documents through a series of stages.

Stage Purpose SQL Equivalent Example
$match Filters documents, similar to a find() query. WHERE { status: "Active" }
$group Groups documents by a specified key to perform aggregate calculations (e.g., sum, average). GROUP BY { _id: "$dept", total: { $sum: 1 } }
$sort Sorts the documents based on a specified field. ORDER BY { age: -1 }
$limit Limits the number of documents passed to the next stage. LIMIT 5 (Top 5 results)
$unwind Splits array values into separate documents. LATERAL VIEW / CROSS JOIN "$tags"
$project Selects, renames, or removes fields in the output. SELECT { username: "$name", age: 1, _id: 0 }
$lookup Adds matching data from another collection. LEFT OUTER JOIN { from: "orders", as: "products" } 
db.employees.aggregate([ ])

1. $match (Filtering)

2. $group (Aggregating)

3. $sort (Ordering)

4. $limit (Restricting)

5. $unwind (Flattening Arrays)

New document: { name: "Anik", skills: ["Java", "MongoDB"] }

6. $project (Reshaping Documents)

7. $lookup (Left Outer Join)


New collection "departments"
[{ dept_name: "Engineering", manager: "Someone" }]

$lookup: {
  from: "second collection name",
  localField: "field from collection_1 which have common values in collection_2",
  foreignField: "field from collection_2 which have common values in collection_1",
  as: "output array name"
}
The Importance of Sequence

The power of the pipeline comes from chaining stages together. The order matters! The output of one stage becomes the input for the next. For performance, it's almost always better to filter first with $match to reduce the number of documents processed by later stages.

Recommended Sequence (Best Performance)
1. $match
Filter Early
→
2. $sort/$limit
Reduce Size
→
3. $lookup
Join Data
→
4. $project
Reshape
Sequences to Avoid (Performance Killers)
  • $unwind before $match
  • $lookup before $match
  • $group before $match

Lab: Storing Files with GridFS

GridFS is a specification for storing and retrieving files that exceed the BSON-document size limit of 16 MB. It divides a file into smaller chunks and stores each chunk as a separate document.

Why do we need this?
Storage Formats
Files < 16MB (Standard)

Stored as a single field inside a document using BinData.

{

  "name": "avatar.png",
  "data": BinData(...)

1 Document = 1 File
Files > 16MB (GridFS)

Split into fs.files (metadata) and fs.chunks (data).

Replication means keeping the same data on multiple MongoDB servers. This group is called a replica set. If one server fails, another one can take over, so your app stays online.

Sharding (Scalability)

Sharding splits a big collection so different servers each own a slice of the data. MongoDB can then handle more users, more writes, and more records without one server becoming a bottleneck.

Image 1: Cluster Layout
Image 2: Data Flow
Detail Explanation Why It Matters
Application & mongos router The app talks to a router named mongos instead of directly to servers. One router keeps traffic organized and sends each query to the right shard.
Shards (Shard A, B, C) Each shard stores part of the dataset (e.g., customers starting with A-G). Distributes load so no single server is overwhelmed.
Config servers Hold a map of which shard owns which range of data. Mongos uses that map to read/write without guessing.
Request Path With Sharding

Sends read/write

→
mongos Router

Checks config servers' map

→
Target Shard

Handles the data slice

Easy phrasing: Sharding lets many servers share the work while mongos keeps the traffic going to the right place.
Need Single Server Sharded Deployment
Data size Fits comfortably within a single machine (e.g., < 100 GB). Too large for one disk or memory; grows rapidly.
Write throughput Moderate writes (hundreds/sec). High writes (thousands/sec) across diverse keys.
Operational cost Cheaper to maintain. Higher ops cost but required for scale.

HTML, CSS and JS

HTML: The Structural Bones

What is HTML? HTML (HyperText Markup Language) is the standard language for creating web pages. It defines the structure and content of a webpage using elements like headings, paragraphs, links, and images.
Analogy: Just like the human body has bones that provide structure and support, HTML provides the basic structure for web pages. Without bones, the body would collapse; without HTML, there's no foundation for content.
Example: Building a house - HTML is like the blueprint and foundation. You need the walls and rooms defined before you can decorate.
How to Use HTML: Start with a basic structure: <!DOCTYPE html>, <html>, <head>, <body>. Use tags like <h1> for headings, <p> for paragraphs, <a> for links. Save files with .html extension and open in a browser.

Workflow: How HTML Works

1. Start with <html> (the body)

2. Add <head> (the brain - metadata)

3. Create <body> (the main structure)

4. Use elements like <h1>, <p>, <div> (bones and organs)

↓

Result: A structured webpage ready for styling

CSS: The Skin, Muscles & Clothes

What is CSS? CSS (Cascading Style Sheets) is a language used to describe the presentation of a document written in HTML. It controls the layout, colors, fonts, and overall appearance of web pages.
Analogy: CSS is like the skin, muscles, and clothes that make the body look good and function properly. While bones provide structure, CSS adds color, shape, and movement.
Example: Interior design - CSS is like painting walls, arranging furniture, and adding decorations to the house built with HTML.
How to Use CSS: Link a CSS file to HTML using <link> in the <head>, or use <style> tags. Use selectors to target HTML elements and apply properties like color, font-size, margin. For Bootstrap, include the CDN link and use pre-built classes.

Visual Workflow: How CSS Works

1. Link CSS file to HTML

2. Select elements (bones) to style

3. Apply properties like color, size, position

4. Use selectors, classes, IDs for precision

Result: A beautiful, styled webpage

JavaScript: The Brain & Behaviors

What is JavaScript? JavaScript is a programming language that adds logic, interactivity, and dynamic behavior to web pages. It can read and change HTML/CSS, respond to user actions, and connect to back-end services.
Analogy: If HTML is bones and CSS is skin/clothes, JavaScript is the muscles and nervous system that make the body move and respond.
Image Prompt: Visualize a person thinking, moving arms and legs, and reacting to a button push. That is JavaScript making a page interactive.
Real-World Example: A traffic light system (green/red/yellow) changing states based on time and sensors is like JS reacting to events and updating the UI.
How to Use JavaScript: Place JS inside <script> tags in HTML or load an external .js file using <script src="app.js">. Use event listeners, functions, and DOM methods (querySelector, addEventListener) to make changes.

Workflow: HTML vs CSS vs JS

  • HTML: structure (tags and content)
  • CSS: style (color, layout, fonts)
  • JS: behavior (events, animation, data handling)

In MERN:

  • Node.js: Server executes JS on backend
  • Express: API layer for routing requests
  • React: Frontend JS library with component-driven UI
  • MongoDB: Database storing JS-serializable data (JSON/BSON)
